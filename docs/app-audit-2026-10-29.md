# Application audit — 29 October 2026

## Scope

Reviewed registration and credentials login, sessions and rate limits, the API router, report authorization and status services, profile uploads, browser flows, email delivery, deployment settings, and direct production dependencies. The affected person's email and signup response were not available, so the exact account failure cannot be confirmed from their attempt.

## Confirmed defects fixed

| Area | Finding | Change |
| --- | --- | --- |
| Hosted login | A newly registered person using the old demo password was rejected in production despite having a valid account and hash. Production also accepted `@demo.test` registrations that could never sign in. | Existing non-fixture accounts can sign in. New production registration rejects demo details before saving the account. |
| Login feedback | Auth.js or database failures could appear as “Email or password is incorrect.” | Only a credentials rejection gets that wording; other failures show a service message. |
| Shared rate limits | Without a configured proxy header, all visitors used one IP bucket: 10 login attempts per 15 minutes and 3 registrations per hour for the whole site. | Vercel now uses its overwritten `x-forwarded-for` client address. Other hosts retain the conservative fallback until a trusted proxy is configured. |
| Avatar upload | The UI accepted photos up to 2 MB, while the shared API reader rejected JSON above 16 KiB. | The avatar route now permits up to 3 MiB of JSON to carry a 2 MiB base64 image. |
| Profile claims | The profile described self-entered details as university verified and synchronized, and described every report as strictly confidential. | Wording now matches the actual account and report access rules. |
| Interface details | A decorative PNG was served with a `.jpg` name, avatar images had no intrinsic dimensions, a staff menu announced itself as a student menu, and several transitions animated every CSS property. | Corrected the asset name, dimensions, menu label, focus styling, and transitions. |
| Dependencies | Auth.js and the app's SMTP mailer had high or critical advisories. | Updated to `next-auth@5.0.0-beta.32` and `nodemailer@10.3.1`. Clean installs use `.npmrc` because Auth.js's unused optional mailer peer range has not caught up to v10. |

## Open findings and decisions

1. **Identity and recovery:** Anyone can register an unverified email address, and the app has no password reset. Before accepting real incidents, add verified ownership and a secure recovery flow. A mistyped address also cannot be corrected in the UI.
2. **Remaining dependency advisory:** `npm audit --omit=dev --audit-level=high` reports three high severity dependency-tree findings from `deepmerge-ts` in the Prisma 6 development CLI. Its automated fix requires Prisma 7, a major migration. Review that migration separately with database and deployment tests.
3. **Campus network limits:** Even with per-client IPs, the 3 registrations per hour limit may be too small for shared campus networks. Select limits from expected traffic and add edge protection before real use.
4. **Draft continuity:** `src/components/reports/report-form.tsx:41` does not warn before navigation with unsaved incident text. `src/components/reports/reports-list.tsx:18` keeps filters only in component state, so they reset on refresh. These are lower priority interface improvements.
5. **Operational readiness:** The actual hosted environment, its recent request logs, the affected account, email ownership, incident handling staff, and external contact availability were not verified by this source audit. No production database records were changed.

## Verification

Verification completed: `npm run check:syntax`, `npm run check:access`, `npm run typecheck`, 39/39 tests in `npm test`, 7/7 browser cases in `npm run test:e2e`, and `npm run build`. A clean-install dry run passed. `npm audit --omit=dev --audit-level=high` reports the Prisma CLI dependency finding described above. A successful local suite does not validate the deployed environment or prove the cause for one person's account without their email and signup result.
